## 0. 一句话结论

国内拼豆图纸生成器已经是一片红海，但**没有任何一家做真实的 AI 流程**：所谓"AI"基本是命名与话术，实际做法是"像素化 + 最近色匹配 + 若干规则开关"。真正稀缺的不是功能，是**判断与解释**。

同时发现一个高价值基线：**Hon-Wong/pindou**（浏览器端、开源、功能最完整），可以直接作为"成熟基础功能"的参照乃至起点。

## 2. 逐个分析

### 2.1 Hon-Wong/pindou —— 最值得研究的基线

**页面底部给出源码地址：`https://github.com/Hon-Wong/pindou`**（仓库本身本轮无法访问）。

已证实的特性（页面原文）：

- **7 套色卡、共 1392 色**，色值标注为"常见拼豆色卡的近似值"；支持自定义 CSV、保存"我的色卡"、导出。
- **六种采样方式**：感知优化、面积平均、**DPID 细线增强**、边缘保留、主色/众数、最近邻。
- **三种量化算法**：K-Means（Lab 空间）、中位切分、直接匹配色卡。
- 抖动：无 / Floyd–Steinberg / 有序抖动，强度可调。
- 图像微调：亮度、对比度、饱和度、伽马；预模糊、锐化、纹理强度。
- 背景移除：容差、透明阈值、吸管取背景色。
- 裁切：填充裁切 / 完整包含 / 拉伸变形。
- **六类一键预设**：照片、动漫插画、像素画、扁平 Logo、单色剪影、最大保真。
- **真实感预览**：豆子形状、熨烫程度、表面工艺、闪粉色、观察面。
- 导出：图纸 PNG（色号 + 图例）、成品预览 PNG、色号表 CSV、**参数 JSON 导入导出**。
- 纯前端，图片不上传。

**判断**：这基本是"成熟基础功能"的完整集合，且**可复用的工程资产密度最高**。它已经解决：多色板、多采样策略、Lab 量化、抖动、背景移除、预设、真实感预览、参数序列化。

**它没有的**：语义感知（不分主体/背景的权重）、质量诊断、解释、成本估算、跨品牌等价、可行性预判、局部区域修改（所有参数都是全局的）。

> 注意：它的"参数 JSON 导入导出"已经是一种轻量的"可复现"实践，说明这个团队也认为**记录配方**有价值——但不是用来保证随机生成的同一性。

### 2.2 beadsheet.com —— 施工图交付最完整

- 色板：MARD 221/291、Perler 103、Artkal S 199、Hama Midi 92。
- **"只用我手上有的颜色"**，可保存"我的色号"。
- 板规格：29×29、52×52、50×50，可自定义；豆径 2.6mm / 5mm。
- **分板：1×1 到 4×4，以及 2×1、1×2、3×2、2×3 等横竖组合**，PDF 按板分页。
- **图纸质量最高**：格内印符号+色号，粗线间隔 5/10 可选，Letter/A4，**按豆子实际大小打印**。
- **用量 CSV 含 10% 损耗和袋数**（每袋 500/1000/2000 可设）。
- 无 AI；无成本金额；无诊断。

**判断**：它把"交付物"这一层做穿了。这是最容易被误判为差异化、实际上已经饱和的部分。

### 2.3 beadary.com —— 色彩参数最细

- 四套色盘，色数最精确：Perler Midi 124、Hama Midi 88、Artkal S 225、MARD 291；按套装范围（24–291）限制候选色。
- **一张图纸只用一个品牌，不混用**——这是个值得注意的产品约束，也说明跨品牌等价确实没人做。
- 限色 8/12/16/20/自定义。
- **五种抖动算法**（Floyd–Steinberg、Atkinson、Sierra、Stucki、Burkes），强度连续可调。
- 分板 1–3 板宽，PDF 含每色用量。
- 背景去除（容差可调，适合渐变背景）。

**判断**：这是"参数化路线"的典型代表。参数很全，但全部是全局标量，用户只能靠试。

### 2.4 pixelbead.art / pixel-beads.com / perler.gujiakai.top

三者的共同点：多品牌色板 + 套装范围筛选 + 本地处理 + PNG/PDF/CSV。差异化很弱，主要竞争点在 SEO 与"免费"。

`perler.gujiakai.top` 值得一提：**7 套 1392 色**、宽度/缩放/抖动/参考线，纯浏览器处理。

### 2.5 pindouai.app —— "AI"命名与实际做法不符

页面原文：站点名"拼豆AI"，首页称"智能工具站""智能计算色彩"，FAQ 称"算法会自动为你匹配最接近的色号"。

实际描述的处理只有两步：**像素化**和**最近色匹配**。可调参数只有尺寸与品牌色板。流程是"一键"、"一秒钟"。

另一个页面（generator）描述"一键优化"：**自动剥离杂乱背景、提取清晰黑线轮廓、转换纯色风格**。

**判断**：名字带 AI，但描述出来的每个动作都是经典规则/传统 CV。没有多模态、没有语义理解、没有生成式。这是典型的 **AI 话术包装**。

### 2.6 perlerlab.com

仅取到标题："2026免费AI图片转拼豆工具"。正文未取到，**无法判断**。仅记录：AI 出现在标题，而非功能描述。

## 3. "伪 AI"的三种典型模式

这是本次调研最值得记录的产品观察。

| 模式 | 表现 | 实例 |
| --- | --- | --- |
| **命名 AI 化** | 产品名/标题带 AI，功能描述里没有任何模型 | pindouai.app、perlerlab.com |
| **把规则叫智能** | "智能计算色彩"= 最近色匹配；"自动优化"= 阈值去背景 + 边缘检测 + 色阶压缩 | pindouai.app 的"一键优化" |
| **把一键叫 AI** | 一次性完成、参数不可见、过程不可介入，用"快"制造智能感 | 多数产品 |

**重要判断**：问题不在于"用了规则"。规则是对的、稳定的、便宜的。**伪 AI 的真正问题是把规则包装成不可解释的黑箱**——用户看不到中间状态，无法介入，无法学习，无法局部修正。

这正好反向定义了我们的机会：**不是用模型替代规则，而是用模型决定"何时用哪条规则、用多少、以及怎么解释"。**

## 4. 为什么"一键优化"不可控

拆开它的三个动作看：

| 动作 | 实际算法 | 用户能控制什么 | 出问题时能修什么 |
| --- | --- | --- | --- |
| 剥离杂乱背景 | 底色阈值 / 连通域 | 无（或一个容差） | 如果误删了主体的一部分，只能整体撤销 |
| 提取黑线轮廓 | 边缘检测 + 阈值 + 细化 | 无 | 如果轮廓多出一圈毛刺，无法只删这一处 |
| 转换纯色风格 | 色阶压缩 / 最近色 | 无 | 无法知道是哪一步导致的失真 |

**三个致命点**：

1. **复合动作不可分离**。三步串成一个按钮，用户的满意度无法归因到某一步。
2. **不可局部修正**。拼豆图纸是"要照着拼几小时"的东西，用户经常只需要改 5 个格子；一键重算会破坏已经认可的部分。
3. **没有"预期效果"**。点之前不知道会变成什么样，只能点完再看——这就是"死马当活马医"的心理成因。

## 5. 为什么五种抖动算法是"死马当活马医"

抖动本身是正确技术（用有限色制造中间调），但在这些产品里的用法有问题：

- **全局标量**：一个强度作用于整张图，而不是"只在皮肤过渡区用"。
- **没有目标函数**：没有任何指标告诉用户"抖到 3 比抖到 5 更接近原图"。
- **没有代价提示**：抖动会增加豆子种类和数量，把"少买豆"的目标反向推走，但界面不说。
- **物理不可预期**：屏幕上像渐变，拼出来是散点；用户要在拼到一半才发现。
- **不可局部撤销**：改一处必须全图重算。

所以它确实只能承担"不满意时再试一下"的功能。**真正的解法不是提供更多抖动算法，而是把抖动变成有适应症、有剂量、有疗效评估的"治疗手段"**：

- 只在检测到"平滑渐变被切成硬边"的区域启用；
- 剂量按"该区域 ΔE 改善量 vs 新增豆子数"自动选；
- 应用前给出"预计改善 ΔE 2.1、多用 18 颗豆"；
- 应用后实测，不达标就回退。

## 7. 对我们的启示

1. **基底直接借鉴，不要重写**。Hon-Wong/pindou 已覆盖采样、量化、抖动、预览、序列化；beadsheet 已覆盖分板与施工图。把精力放在空白列。
2. **AI 的位置必须与竞品的"AI"形成对照**。他们用 AI 做命名，我们用 AI 做**判断**：语义重要性、诊断、解释、取舍建议。
3. **不要比"功能多"**，要比"每一步都知道为什么"。竞品的按钮越多，用户的困惑越大；我们的按钮越少，解释越充分。
4. **全局参数是共性问题**。所有竞品都是"整图一套参数"，没有区域级控制。这是最实在的产品空位，也是语义感知唯一能落地的地方。
5. **"一键"是竞品的卖点，也是它的天花板**。我们不该争"更快的一键"，而该做"一次点击之后还能继续收敛"。
