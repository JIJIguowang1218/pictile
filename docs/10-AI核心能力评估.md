# AI 核心能力评估 v0.1

> 目的：回答三个问题——**AI 在我们产品里到底是什么、和规则系统怎么配合、LLM 以什么形式存在。**
> 关联：[`04-问题地图与AI价值边界`](04-问题地图与AI价值边界.md)、[`05-技术调研-P1P2P3`](05-技术调研-P1P2P3.md)、[`07-关于可复现性的讨论`](07-关于可复现性的讨论.md)、[`08-检查项清单`](08-检查项清单.md)

## 1. 总判断

> **AI 是"建议引擎 + 解释引擎"，不是"渲染引擎"。**

三条不可越过的线：

1. **不产数值**。所有数字来自确定性工具，AI 只能引用与排序。
2. **不直接改图**。AI 只能提议动作，动作必须经 `simulate` 验证并由用户确认。
3. **不默认介入**。默认路径零 AI 调用；AI 由指标触发或用户主动开启。

在这个前提下，AI 的价值不是"把图做得更好"，而是**替用户吸收判断**：该保留什么、该牺牲什么、为什么、值不值。这正好是竞品用一堆全局滑杆推给用户的那部分。

## 2. 三引擎架构

```
┌─────────────────────────────────────────────┐
│  规则引擎（Deterministic Core）              │
│  采样 · 量化 · 清理 · 排版 · 渲染            │
│  纯函数 / 可复算 / 零成本 / 浏览器本地        │
└───────────────┬─────────────────────────────┘
                │ 产出图纸 + 中间数据
┌───────────────▼─────────────────────────────┐
│  测量引擎（Measurement）                     │
│  检查项注册表（08）· simulate · 代价计算      │
│  确定性 / 可审计 / 给出证据                   │
└───────────────┬─────────────────────────────┘
                │ 结构化证据（数值 + 区域 ID）
┌───────────────▼─────────────────────────────┐
│  语言引擎（LLM / VLM）                       │
│  语义测量 · 选题 · 措辞 · 意图定位            │
│  无状态 / 可失败 / 必须降级                   │
└─────────────────────────────────────────────┘
```

**分工的一句话版本**：
规则引擎决定"事实"，测量引擎决定"证据"，语言引擎决定"怎么问、怎么说"。

**为什么必须分开**：混在一起的后果是"模型说了算"。而拼豆图纸要被照着执行几小时，用户需要的不是惊喜，是可信。

### VLM 的特殊位置

VLM 同时跨在测量与语言之间，但它的测量是**定性判断题**，不是数值：

- ✅ "眼睛还在吗" / "这版像不像本人" / "A 和 B 哪个更像"
- ❌ "色差 8.4" / "这里有多少颗豆" / "第 12 行第 7 格错了"

它补上的是规则系统**原理上做不到**的那一层：语义与取舍。

## 3. 能力矩阵

| 能力 | 实现形式 | 价值 | 风险 | 成本 | 版本 |
| --- | --- | --- | --- | --- | --- |
| 主体 / 背景分割 | 轻量分割模型 | **高**（分区精度的前提） | 低 | 低 | v1 |
| 人脸 / 五官定位 | MediaPipe / YuNet | **高**（低分辨率保五官） | 低 | 极低 | v1 |
| 显著性权重 | 传统 CV + 人脸先验 | 高 | 低 | 零 | v1 |
| 特征清单核对（C12） | VLM 判断题 | **高**（第一个真 AI 面） | 中 | 低 | v1.1 |
| 成对候选排序 | VLM 成对 + 换位 + 多票 | 高 | 中（位置偏置） | 低 | v1.1 |
| 诊断措辞 | LLM 读结构化报告 | 中高（体验层） | 低 | 低 | v1.1 |
| 检查项重排（选题） | LLM 从 ≤5 菜单选 | 中 | 中 | 低 | v2 |
| 对话定位（"左边耳朵"） | LLM + Grounded-SAM | 高 | 中高 | 中 | v2 |
| 记忆色先验 | VLM | 中 | 中 | 低 | v2 |
| 照片风格迁移 | 生成模型 | 中 | 高 | 高 | 待定 |
| 文本生图 | 生成模型 | 低 | 高 | 高 | **不做** |
| VLM 自动闭环改图 | VLM critic 自迭代 | **负**（研究显示会退化） | 高 | 中 | **不做** |

**读法**：价值高的集中在"语义判断"与"表达"；风险高的集中在"生成"与"闭环"。这不是巧合——**模型越靠近像素，风险越高；越靠近语言，风险越低。**

## 4. LLM 的存在形式

| 形式 | 说明 | 输入 | 输出 | 失败模式 | 降级 |
| --- | --- | --- | --- | --- | --- |
| **F1 无状态结构化函数** | 单次调用，JSON schema，低温 | 图 + 指标 + 区域 ID | 结构化 JSON | 解析失败、越界 | 丢弃，用模板句 |
| **F2 选题器** | 从固定菜单挑 ≤5 条检查项并排序 | 图像特征摘要 + 检查项表 | 有序 ID 列表 | 选出不适用的项 | 回退规则触发 |
| **F3 多轮代理** | tool calling，多轮定位与追问 | 对话 + 上下文 | 动作 + 参数 | 幻觉工具、循环 | 超步数即中止 |
| **F4 离线评估器** | 不面向用户，用于标注与回归 | 批量样本 | 评测结果 | 偏差污染数据集 | 人工复核 |
| **F5 本地小模型** | 隐私/离线场景 | 同 F1 | 同 F1 | 质量下降 | 切云或降级 |
| **F6 提示词资产** | 版本化的模板库 | — | — | 版本漂移 | 锁定版本号 |

### 4.1 v1.1 采用：F1（两处）+ F6

- **F1-a 特征清单核对**：输入源图 + 图纸渲染图 + 特征清单，输出逐条 `present/partial/lost`。
- **F1-b 诊断措辞**：输入结构化诊断（检查项、数值、区域、动作、代价），输出 1–2 句中文。
- **F6**：所有提示词版本化，与 `check_id` 绑定，可回归。

### 4.2 v2 采用：F2

仅当"规则触发 + 全部检查项"的成本或噪音成为问题时，才引入选题器。**引入的前提是有离线评测证明它比规则更好**。

### 4.3 v2+ 才考虑：F3

对话定位是唯一需要多轮的场景。但即使到 F3，**动作仍走白名单 + simulate 验证**，模型不获得"自由改图"权限。

### 4.4 一条硬性架构约束

> **LLM 无状态；状态放在应用层。**

会话状态 = 版本栈 + 当前配方 + 区域注册表。每次调用都把必要上下文重新喂进去。好处：

- 可审计：每次调用都能重放
- 可回退：撤销的是应用层的一个版本，不是模型记忆
- 可换模型：换供应商不影响产品行为
- 不漂移：不会因为"模型记得上次说过什么"而改变判断

## 5. 与规则系统的配合契约

| 契约 | 内容 | 违反的后果 |
| --- | --- | --- |
| **输入契约** | 结构化输入（指标 + 区域 ID + 候选动作 + 代价），不给原始像素（VLM 语义判断除外） | 模型开始"看图编数" |
| **输出契约** | JSON schema + 枚举 + 参数范围；schema 校验不过即丢弃 | 产生不可执行动作 |
| **失败契约** | 超时 / 解析失败 / 越界 → 静默丢弃，走确定性路径 | 阻塞主流程 |
| **验证契约** | 动作必须 `simulate`；预测改进 < 阈值 → 驳回并回灌 | 建议无效却消耗信任 |
| **幂等契约** | 同一输入可产出不同建议；**被采纳的建议落成参数** | 用户认可的结果被"重新理解" |
| **置信契约** | 每个 AI 结论带 confidence；低于阈值只作"参考"或不出 | 过度自信 |

### 5.1 规则系统负责"什么时候不用 AI"

这是最容易被忽略的一半。规则引擎必须能回答：

- 这张图的主流问题是否已在确定性可解范围内？（是 → 不调 AI）
- 当前预算/延迟是否允许？（否 → 不调 AI）
- 上次同类图 AI 建议的采纳率是否过低？（低 → 不调 AI）

**"不用 AI"的能力，和"用 AI"的能力同等重要。**

## 6. 成本与延迟预算（量级估算）

| 路径 | 调用 | 延迟 | 单图成本 |
| --- | --- | --- | --- |
| 默认路径 | 0 | 0 | ¥0 |
| 确定性体检 | 0 | <50ms | ¥0 |
| + 诊断措辞（F1-b） | 1 次文本 | 1–3s | < ¥0.01 |
| + 特征核对（F1-a） | 1 次双图 | 3–8s | ¥0.01–0.05 |
| + 成对比较（3 候选） | 3 次（换位 ×2 + 多票） | 5–10s | ¥0.02–0.10 |
| 对话（F3） | 2–5 次 | 5–20s | ¥0.05–0.20 |

**策略**：AI 结果以"追加"方式到达，不阻塞首图；用户先看到确定性结果，再看到解释。

## 7. 如何证明 AI 有用

### 7.1 离线

| 实验 | 样本 | 指标 | 通过线 |
| --- | --- | --- | --- |
| 成对偏好一致性 | 200 对人工标注 | 与人类一致率 | ≥ 0.65 |
| 换位一致性 | 同上 | 交换 A/B 后结论不变的比例 | ≥ 0.80 |
| C12 特征核对 | 200 张 × 5 特征 | present/partial/lost 与人工一致率 | ≥ 0.75 |
| 措辞可用性 | 100 条 | 人工打分（1–5）"是否可据以决策" | ≥ 3.8 |

### 7.2 在线

| 实验 | 指标 | 通过线 |
| --- | --- | --- |
| 灰度 A/B | 首次接受率提升 | ≥ 5pp |
| 灰度 A/B | 决策数不增加 | 不劣化 |
| 采纳率 | 建议被采纳比例 | ≥ 40% |

### 7.3 否决线

任一条件成立 → 该 AI 能力不上线或回退：

- 成对一致率 < 0.60
- 换位一致性 < 0.75（位置偏置过强）
- 灰度提升 < 3pp 且成本 > ¥0.02/图
- 解析失败率 > 2%

## 8. 风险登记

| 风险 | 触发条件 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 幻觉特征 | 图纸细节模糊 | 建议错误 | 特征清单 + 双图输入 + 多票 |
| 位置偏置 | 成对比较 | 结论随顺序翻转 | 双向交换 + 任一翻转即降级为"不确定" |
| 颜色判断不可靠 | 任何涉及色值的判断 | 严重误导 | **禁止**，色值一律走 ΔE |
| 模型漂移/下架 | 供应商更新 | 行为突变 | 锁定模型版本；季度回归 |
| 成本波动 | 涨价 | 单位经济崩塌 | 默认零 AI；分级调用 |
| 隐私泄漏 | 人像上传 | 法律与信任 | 默认本地；显式授权；24h 删除 |
| 中文表达质量 | 措辞生成 | 读起来像机翻 | 固定句式模板优先，LLM 仅微调 |
| 过度解释 | 每条都给长篇 | 干扰决策 | 每条 ≤2 句；无代价不呈现 |

## 9. 明确不该做的地方

| 不该做 | 原因 |
| --- | --- |
| 用模型做采样 / 量化 / 渲染 | 可复算与可控性丧失，且算法更优 |
| 让模型输出色值、数量、坐标 | 实测准确率极低（见 `05` §4） |
| 自动应用模型建议 | 无法验证，且用户失去控制感 |
| 自由编排工具 | 不可预测、成本不可控、无法验证 |
| 让模型持有会话记忆 | 行为漂移、不可审计 |
| VLM 自动闭环改图 | 研究显示无外部验证时会退化 |
| 文本生图作为主入口 | 成本与控制性双输，且非当前痛点 |

---

## 10. 结论与路线

1. **我们的 AI 不是模型能力，而是"检查项 + 阈值 + 偏好数据"的组合。** 模型是可替换的，注册表与标注集是资产。
2. **v1 的 AI 触点只有两个**：C12 特征核对、诊断措辞。二者都远离像素，风险最低、感知最强。
3. **v2 才引入选题与对话**，且必须先有离线评测证明优于规则。
4. **永远保留一条完全无 AI 的路径**，它是产品的地板，也是竞品对比时的底线。
