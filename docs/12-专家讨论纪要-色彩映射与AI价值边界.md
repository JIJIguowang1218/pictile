## 0. 一页结论

### 与现行判断一致（无需改方向）

1. **转换主引擎是确定性算法**：采样、量化、色板约束、可拼性清理、排版，全部规则化。
2. **VLM 不判色、不计数、不产数值**：色彩一律走 CIEDE2000 + Lab，VLM 只做语义判断。
3. **AI 的价值在"意图翻译 + 解释 + 候选排序"**，不在"生成"。
4. **衡量标准是用户决策数**，不是"AI 让图更准"。

### 真正的新增（值得入库）

1. **格内代表色提取的六种取法**，以及"多峰分布"导致的丢小物体/糊边界机制。这比"选哪个插值核"更影响成品质量，是 v1 内核里被低估的一个决策。
2. **内容感知降采样的学术清单**：Gerstner & DeCarlo 2012、SLIC、Felzenszwalb 图分割、Secord 加权 Voronoi、以及 SAM 作为区域引导工具。补齐了 `05` 只提到 Depixelizing / seam carving / guided filter 的缺口。
3. **VLM 做"修图意图解析"的外部证据**：VeraRetouch、IEA、AceTone。它们支撑"自然语言 → 结构化参数 → 确定性执行"这条架构，但**参数集不能照搬**（见 §6.3）。
4. **国内色卡的梯队化信息**（MARD 221/291、优肯 418/197/M221、COCO、漫漫、盼盼、咪小窝）。这是对 `05` §7.2 的细节补充，但**可信度低于已核验的 MARD/Artkal 事实**。

### 需要修正的倾向

**不要把"亮度/对比度/色温"这类修图参数当成拼豆的交互目标。** 外部讨论引用的 VeraRetouch / IEA 是通用照片修饰研究；拼豆的动作空间应该是 `08` 里的 A01–A14（提高局部采样、加描边、换子集、区域抖动、重裁、反补偿等），而不是曝光/对比度滑块。架构可以借，参数不能借，否则产品退化成"又一个修图器"。

### 需要复核的风险

- 讨论中的色卡梯队和学术引用均无链接，属于"候选清单"而非"事实清单"。
- "主流度 S / 5.0"这类打分没有可追溯来源，不应进入对外材料。

### 1.2 对产品的含义（讨论主张，与现行规格一致）

"店铺色不够"是常态，不是异常。产品层面的决策不是算法问题，而是：

- 默认色卡锚定 MARD 221；
- 内置多品牌色卡，允许切换；
- 允许用户排除"我没有的颜色"后重映射；
- 明确"补货建议"而不是假装色板齐全。

**与现行规格对照**：`09` PD-04 已定 v1 用 MARD 221 + Perler 103，Artkal 放 v1.1；`05` §7.1 记录 beadsheet 已支持"只用我手上有的颜色"。所以这一条**不构成新决策**，只是确认方向正确。

## 2. 色彩近似映射管线（信息记录）

### 2.1 四步串联（讨论版本）

```
原图 → ①降采样（固定网格）→ ②色彩量化 → ③色板约束映射 → ④可拼性后处理
```

讨论强调：**拼豆映射不是一次降采样，而是"有限色板下的感知最近色匹配 + 可拼性清理"的约束优化。** 这与 `02` §1 的流水线、`05` §2.1 的"给定色板选子集"一致。

### 2.2 格内代表色：六种取法与多峰问题（新增细节）

每个输出格子对应原图一个矩形区域。讨论给出的取法对比：

| 取法 | 机制 | 问题 |
| --- | --- | --- |
| 点采样（nearest / bilinear） | 取中心点或插值 | 最容易丢小物体，一个像素决定整格 |
| 区域平均（box filter） | 区域内 RGB 平均 | 边界跨格时平均成"脏中间色"，小物体被稀释 |
| 中位数 | 各通道中位数 | 比平均抗极端值，但仍会混合 |
| 众数 / 主导色 | 区域内出现最多的颜色 | 对色块图好，对渐变图会跳变 |
| 聚类中心 | 区域内 K-means 取主簇 | 能识别"这格有两种主色"，但单格只能输出一个色号 |
| 加权平均 | 按重要性 / 距离加权 | 比均匀平均好，权重设计是关键 |

**核心机制（讨论原文的判断）**：

- **丢小物体**：物体投影面积小于一个格子面积时，平均值会把物体和背景混成"既不是物体也不是背景"的中间色。
- **糊边界**：边界跨两个格子时，每格都含两侧颜色，平均后变成 2 格宽的渐变带，产生锯齿。
- **纹理摩尔纹**：高频纹理在规则网格下产生摩尔纹。

**结论**：规则区块采样**结构性地**会丢东西，调插值核只能改善平均方式，不能恢复多峰分布里的少数派。

### 2.3 与现有文档的关系

- `02` §2.1 已写"面积平均 / 中值，LAB 空间，边缘感知取主导色"，但**没有把"多峰分布"和"六种取法"讲透**。本节是实质性补充。
- `05` §1.3 强调"非均匀采样 / 按重要性分配精度"，与讨论的"内容感知降采样"一致。
- **建议**：v1 内核应增加"方差门控 + 主导簇"策略，并把方差大的格子标记为"细节冲突格"，在前端高亮（对应 `08` C01/C02 的证据面）。这是一个**待决项**，见 §7。

### 2.4 色板约束与子集选择（讨论主张，与现行一致）

- 匹配目标必须是**真实在售色卡**，不能生成任意 RGB。
- 色彩空间用 Lab / CIELAB，色差用 CIEDE2000。
- 主流库解决的是"自由减色"，不是"从固定色板选 N 色子集"；后者是设施选址 / k-medoids 问题，规模很小，贪心 + 交换精化即可。
- 抖动是可选而非默认：Floyd–Steinberg 能保留纹理，但会产生细碎色块，默认应"干净可拼"。

**与现行文档的关系**：`05` §2.1、§2.3 已完整覆盖，本次无新增结论。

### 2.5 一句讨论原文（值得保留的产品表达）

> "你的这套豆子里最接近这个蓝紫的是 S22，它会比原图暗一档、偏灰。换成 S18 更亮但会偏紫。这块区域建议直接用深色描边吃掉，反而更精神。"

这段话的价值在于：**每个数字都来自确定性计算，LLM 只负责组织语言。** 这正是 `10` F1-b"诊断措辞"的形态。

## 3. 降采样、区域与边界（信息记录）

### 3.1 规则网格为什么会失效（讨论版本）

与 §2.2 同源，讨论从几何角度补了三句：

1. 物体小于一格 → 平均值稀释，视觉上消失。
2. 边界跨格 → 混叠，锯齿 + 2 格渐变带。
3. 高频纹理 → 摩尔纹。

**关键判断**：这是结构性问题，不是调参能解决的。

### 3.2 内容感知降采样的六条路线

| 路线 | 核心思想 | 对拼豆的适用性 |
| --- | --- | --- |
| 重要性图驱动 | 显著性 / 边缘图加权降采样 | 保护显著区域和小物体；固定网格下可用 |
| 超像素引导（SLIC） | 按超像素占比取主导色 | 边界格自然偏向某一侧 |
| 图分割引导（Felzenszwalb） | 先分感知一致区域，再决定格子归属 | 区域识别基础 |
| 感知像素化（Gerstner & DeCarlo） | 由感知模型决定像素大小与位置 | 拼豆格子固定，只能借"显著性加权"思想 |
| 内容感知缩放（Seam Carving） | 保护重要内容、压缩次要区域 | 用于构图裁剪，不用于降采样 |
| 边缘保持预处理（Guided Filter） | 先平滑噪声、保住边缘，再降采样 | 减少边界糊化，低成本高收益 |

### 3.3 学术文献清单（讨论提供，均需复核）

| 文献 / 方法 | 核心思想 | 状态 |
| --- | --- | --- |
| Gerstner & DeCarlo, *Pixelated Image Abstraction*, NPAR 2012 | 感知驱动的自适应像素化 | ⚠️ 未给链接；与拼豆最相关 |
| Kopf & Lischinski, *Depixelizing Pixel Art*, SIGGRAPH 2011 | 像素图 → 矢量边界 | 已在 `05`；⚠️ |
| Felzenszwalb & Huttenlocher, *Efficient Graph-Based Image Segmentation*, IJCV 2004 | 图分割 | ⚠️ |
| Achanta et al., *SLIC Superpixels*, TPAMI 2012 | 超像素 | ⚠️ |
| Avidan & Shamir, *Seam Carving*, SIGGRAPH 2007 | 内容感知缩放 | 已在 `05`；⚠️ |
| He et al., *Guided Image Filtering*, ECCV 2010 | 边缘保持平滑 | 已在 `05`；⚠️ |
| Secord, *Weighted Voronoi Stippling*, NPAR 2002 | 加权点分布优化 | ⚠️ |
| Kirillov et al., *Segment Anything*, ICCV 2023 | 通用分割大模型 | ⚠️；`05` 已列 SAM 2 / MobileSAM |
| CIEDE2000（Luo et al. 2001） | 感知色差 | 已在 `05`；✅ |
| Heckbert 1982 / Wu 1991 | 中位切分 / 最优量化 | ⚠️ |

**注**：文献的存在性基本可靠，但讨论没有给出链接、版本或具体结论。按 `05` 的政策，标 ⚠️ 的条目只能当候选清单，不能作为"已核验事实"进入对外材料。

### 3.4 讨论推荐的管线

**MVP（可讲清楚、可测试）**

1. Guided filter 保边平滑。
2. 区域平均 + 方差检测；方差大的格子标记"细节冲突格"。
3. RGB → Lab，CIEDE2000 最近色。
4. 连通域清理，孤立格合并。
5. 细节冲突格在前端高亮，允许用户手改。

**进阶（面试亮点）**

1. 显著性图 + 边缘图 → 重要性加权降采样。
2. SLIC 超像素引导格子主导色。
3. **SAM 做主体分割，保护主体边界**——这是大模型在拼豆里最合理的用途：**区域识别，不是取色**。
4. 边界格用邻域一致性做后处理，减少锯齿。
5. 可选抖动，默认关闭。

**与现行文档的关系**：`05` §1.3 已说"真正的空白是非均匀采样"；`10` 的 v1 能力矩阵已包含轻量分割、人脸、显著性。讨论的贡献是把 **SAM 明确为"区域引导"工具**，并给出可执行的 MVP 顺序。是否把 SAM 放进 v1，是一个待决项（见 §7）。

## 4. AI 价值判断（信息记录）

### 4.1 四问判据（讨论版本）

| 问题 | 如果答案是"否" | 结论 |
| --- | --- | --- |
| 规则 / 算法能不能做？ | 能，且体验差距不大 | 不用大模型 |
| 大模型输出能不能被约束到可执行空间？ | 不能，输出自由文本 / 自由像素 | 不做，不可控 |
| 大模型错了，用户能不能发现并纠正？ | 不能，静默产生坏结果 | 不做，失败成本太高 |
| 这个环节用户是否真的需要语义理解？ | 不需要，滑块 / 按钮就够 | 不做，伪自然语言 |

**讨论的补充判断**：大模型的合理位置只有一个——**语义层**，理解"用户想要什么、哪里不满意、为什么"，翻译成结构化指令，交给确定性管线执行。

**本项目补充第五问：用户是否愿意为这个环节多等 3 秒 / 多付 1 分钱？** 如果答案是否，即使技术上成立，也不该进默认路径（对应 `09` 的"默认零 AI"与 `10` 的成本预算）。

**与 `03` §1.2 的关系**：`03` 的四道判据（目标函数 / 重要性先验 / 主观验收 / 人话）是同一思想的不同切法，二者可合并为一个"上模型前的检查清单"。

### 4.2 逐环节真 / 伪判断（讨论版本）

**预处理**

| 环节 | 规则 / 算法 | 大模型增量 | 判断 |
| --- | --- | --- | --- |
| 去背景 | rembg / SAM 分割 | VLM 解析"只留猫" | **真价值**，但分割用 SAM，VLM 只做意图翻译 |
| 智能裁剪 | 人脸检测 / 中心裁剪 | VLM 看懂"主体在左下" | **中等真价值**，规则能覆盖一半 |
| 参数推荐 | 图像复杂度、边缘密度 | VLM 判断"人物特写 / logo / 风景" | **真价值但轻量**，优势是"看懂内容" |
| 直接生成网格 | — | VLM 出每格颜色 | **伪需求**，不可控、不可复现、违反色板约束 |

**生成后的用户反馈**

| 用户说 | 规则能做什么 | VLM 增量 | 判断 |
| --- | --- | --- | --- |
| "脸太糊了" | 不知道"脸"在哪 | 定位面部区域 → 区域坐标 + 建议 | **真价值核心场景** |
| "背景太花" | 不知道"花"指什么 | 识别背景 → 降低背景色数 / 简化 | **真价值** |
| "轮廓不清楚" | 能算边缘强度，但不知道指哪条边 | 定位主体边缘 → 增强对比 / 关抖动 | **真价值** |
| "整体再亮点" | 全局亮度滑块 | 不需要 VLM | **伪需求**，滑块更好 |
| "把这里改成暖色" | 需要用户圈选 + 调色 | 解析"这里"指代 + 暖色意图 | **真价值**，前提是用户用自然语言 |

**可拼性检查**

| 能力 | 规则 | VLM 增量 | 判断 |
| --- | --- | --- | --- |
| 孤立格、色数、连通域 | 精确计算 | 无 | 规则做 |
| "哪些孤立格值得保留" | 只能全标 | 结合内容判断"眼睛高光该留，噪点该合" | **中等真价值** |
| 用人话解释问题 | 输出数字 | "面部阴影丢失严重，因为色板不够" | **真价值**，解释层 |

**明确伪需求清单（讨论版本）**

- ❌ VLM 直接生成色号网格
- ❌ VLM 做色彩量化 / 色差计算
- ❌ LLM 生成图纸描述再转网格
- ❌ VLM 替代 SAM 做像素级抠图
- ❌ "一键 AI 优化"黑盒
- ⚠️ 纯滑块能表达的调整，硬套自然语言

**与现行文档的关系**：`04` §3、`10` §9 已给出更严格的版本（白名单 + simulate + 用户确认 + 失败降级）。本表可作为**产品沟通用的简化版**，但执行规格以 `10` 为准。

### 4.3 三个可落地的 AI 功能（讨论版本，含接口草案）

#### 功能 1：语义化预处理助手

输入：图片 + 可选自然语言（"只留主体，脸要清楚，背景简单点"）
VLM 输出（受 schema 约束）：

```json
{
  "image_type": "portrait",
  "subject_region": [0, 0, 0, 0],
  "actions": [
    {"op": "remove_background", "target": "background"},
    {"op": "preserve_detail", "region": "face", "priority": "high"},
    {"op": "simplify", "region": "background", "max_colors": 3}
  ],
  "suggested_grid": 64,
  "reason": "人物特写，面部需要更高网格密度"
}
```

执行：SAM 分割 + 规则管线按 actions 跑。VLM 不碰像素。

#### 功能 2：局部反馈修改

交互：用户在预览图上圈选或指着说"这块太糊 / 太亮 / 颜色不对"
VLM 输出：

```json
{
  "region": [0, 0, 0, 0],
  "issue": "detail_loss",
  "adjustments": [
    {"param": "local_sampling_density", "direction": "increase"},
    {"param": "local_smoothing", "direction": "decrease"},
    {"param": "local_palette_size", "direction": "increase", "max": 8}
  ],
  "confidence": 0.82
}
```

执行：规则引擎只对该区域重跑降采样 + 映射，其余不变。
关键设计：VLM 输出的是**区域 + 参数方向**，不是颜色值；用户能看到"改了哪、改了什么"，失败可撤销。

**本项目修正**：`local_sampling_density` / `local_smoothing` / `local_palette_size` 应映射到 `08` 的 A01（`raise_detail`）、A07（局部抖动）、A02/A06（色数/子集），**不要引入通用的曝光/对比度参数**。

#### 功能 3：可拼性解释与建议

输入：网格 JSON + 统计 + 预览图
VLM 输出：人话解释 + 可选项

> "这张图有 22 个孤立单格，其中 6 个在眼睛高光区建议保留，16 个在背景噪点区建议合并。面部过渡只有 3 个色阶，实际拼出来会有明显色块感，是否把面部色数从 3 提到 5？"

执行：用户点"应用"才跑规则。VLM 只建议，不自动改。

**与现行文档的关系**：功能 1/2 对应 `09` 路径 B/C 与 `10` F1/F3；功能 3 对应 `10` F1-b 与 `05` §8.3 的检查项。JSON 草案可作为 v2 接口的起点，但必须过 schema 校验与 simulate 验证。

### 4.4 讨论的一句话架构

> **规则算法做"物理可行解"，分割模型做"区域感知"，VLM 做"意图翻译和解释"，用户做"最终决策"。**

与 `10` §2 的"规则引擎决定事实、测量引擎决定证据、语言引擎决定怎么问怎么说"高度一致。

### 4.5 讨论给出的"如何证明不是伪 AI"

1. **对比实验**：同一张图，"无 VLM 意图层" vs "有"，比较局部修改任务的时间 / 成功率 / 撤销次数。
2. **失败案例展示**：故意让 VLM 直接取色，展示它输出不存在色号、破坏可拼性，论证"为什么不用它做取色"。
3. **Schema 约束展示**：VLM 输出必须过 JSON schema 校验，非法指令直接拒绝。
4. **成本 / 延迟分层**：VLM 只在小环节调用，主流程零大模型依赖，断网也能出基础图纸。

**与现行文档的关系**：`10` §7 已有更量化的离线 / 在线 / 否决线。讨论的四条更适合作为**作品集叙事**，量化口径以 `10` 为准。

## 6. 对项目的启示（评估）

### 6.1 AI 应该介入的环节，按 ROI 排序

| 优先级 | 环节 | AI 形态 | 为什么是它 | 版本 |
| --- | --- | --- | --- | --- |
| 1 | **输入侧的主体/背景/人脸/文字感知** | 轻量分割、MediaPipe、OCR、类型分类 | 这是"区域级控制"的前提；没有它，产品只是全局滑杆像素器。投入低、风险低、杠杆最高 | v1 |
| 2 | **生成后的诊断与解释** | 确定性检查项 + LLM 措辞 | 规则能算数值，但不能把数值变成"人话 + 代价 + 选项"；这是决策数下降的主要来源 | v1.1 |
| 3 | **关键特征核对** | VLM 判断题（带特征清单） | "眼睛还在吗 / 像不像本人"规则做不到；成对判断有量化证据支持 | v1.1 |
| 4 | **候选成对排序** | VLM 成对 + 换位 + 多票 | 证据最强（Pearson 0.636–0.773），风险最低，最适合作为第一个"AI 面" | v1.1 |
| 5 | **意图翻译 / 局部修改** | LLM → 结构化动作 → simulate | 用户说不清时，只有语言模型能把"脸糊了"映射到区域 + 动作；但必须受白名单约束 | v2 |
| 6 | **记忆色先验** | VLM 定性判断 | ΔE 不知道"东亚人的脸不该变橙"；这是 AI 进入 P2 色彩层的唯一合法理由 | v2 |
| 7 | **跨品牌语义补偿** | VLM 内容感知建议 | 切到少色板时，规则很难表达"肤色过渡会变硬"；属于体验增强 | v2 |

**一句话**：AI 的第一价值不是"把图做得更准"，而是**让系统知道"哪里重要、哪里出了问题、用户想改什么"**。前者规则已经做得很好，后者规则做不到。

### 6.2 AI 明确不该介入的环节

- 色号选择、色彩量化、ΔE 计算、豆数/色数/板数统计。
- 网格生成、采样、连通域清理、多板切分、PDF 排版。
- 自动闭环改图（无外部验证时会退化）。
- 文本生图作为主入口。
- 自由编排工具 / 自由发明参数。
- **通用修图参数**（曝光、对比度、色温）作为拼豆的交互原语。

### 6.3 一个必须守住的修正：动作空间是"拼豆动作"，不是"修图参数"

外部讨论引用的 VeraRetouch / IEA / AceTone 证明了"自然语言 → 低层参数 → 确定执行"这条架构可行。但它们的参数集是**照片修饰**的（曝光、对比度、高光、阴影、饱和度、色温、锐度）。如果照搬到拼豆，会产生两个问题：

1. **目标错位**：用户说"脸糊了"，真正有效的动作往往不是"提高对比度"，而是"提高该区采样权重 / 增加局部色数 / 加描边 / 局部抖动"。对比度只是让糊得更明显。
2. **产品退化**：一旦引入这些参数，产品就变成"带拼豆导出的修图器"，与竞品的全局滑杆没有本质区别。

**正确做法**：保留"意图 → 结构化指令 → 确定性执行 → simulate 验证"的架构，但把指令空间限定为 `08` 的 A01–A14，并让每个动作都带代价（Δ色数 / Δ豆数 / Δ分钟 / Δ金额）。这也是 `10` §5 的"输出契约"。

### 6.4 战略层：AI 是差异化的使能器，不是装饰

`05` §7.1 的结论是：竞品功能已饱和，剩下的空白只有"区域级控制、质量诊断、解释、成本、可行性预判"。

这份讨论进一步说明：**这些空白恰好都是规则单独做不到、而感知模型 + VLM/LLM 能做到的。**

- 区域级控制 ← 需要分割 / 人脸 / OCR（感知模型）。
- 质量诊断 ← 需要确定性检查项，但"哪些问题值得说"需要语义判断。
- 解释 ← 需要 LLM 把数值组织成人话。
- 可行性预判 ← 需要 OCR + 内容理解（"中文在 29×29 上拼不出来"）。

所以正确的叙事不是"我们给产品加了 AI"，而是：**"我们发现的唯一差异化是区域级判断，而区域级判断在原理上需要 AI；所以 AI 不是卖点，是使能器。"** 这个叙事比"用了多模态大模型"强得多，也更经得起追问。

### 6.5 度量：决策数仍然是对的，但要防止被"优化"

`04` / `09` 的北极星是"每图决策数 ≤1"。这个指标有一个漏洞：**系统可以靠"少说问题"来降低决策数**，但成品质量会下降。

建议同时看三个指标（`09` 已有，强调其组合关系）：

- 决策数（越低越好）
- 首次接受率（越高越好）
- 诊断采纳后 `severity` 是否真的下降（有效率 ≥80%）

三者必须同时成立，否则"决策数下降"可能只是"系统隐瞒问题"。

**另一个容易被忽略的反向风险：AI 建议本身是决策来源。** VLM 每多给一条建议，用户的决策数就上升。所以 AI 诊断必须遵守与规则诊断相同的上限（最多 3 条、只呈现 `problem` 级、必须带代价），不能因为"AI 看到了"就多说。**AI 的目标是替用户吸收决策，不是展示自己的观察力。**

### 6.6 数据护城河：模型是商品，色表与标注集是资产

讨论再次确认：取色算法本身不是壁垒（300 行 numpy 谁都能写）。真正的资产是：

1. **实测 LAB 色表**（含熨烫前后、批次、仪器）。
2. **检查项阈值**（50–200 张标注集标定）。
3. **偏好标注**（成对比较数据，用于验证 VLM 与人的一致性）。
4. **失败案例分类**（什么图会翻车、为什么）。

这四样都比"换一个更强的模型"更难被抄。

### 6.7 对"AI 产品经理叙事"的启示

这份讨论最大的价值不在技术细节，而在**它示范了一种 AI 产品判断的写法**：

> 先证明规则能做什么 → 再证明 AI 在哪些环节是伪需求 → 最后只在一个窄缝里使用 AI，并用实验证明它有效。

面试/作品集里，最加分的不是"我用了 VLM"，而是：

1. **有边界**：我判断 VLM 不该做取色，因为拼豆的核心约束是色板物理性和可拼性，这两件事 VLM 保证不了。
2. **有证据**：引用 ColorBench 55.4% vs 人类 92%、成对 0.636–0.773 vs 打分 0.490，说明"为什么是成对而不是打分"。
3. **有实验**：预注册指标（一致率 ≥0.65、灰度 ≥5pp），失败就退回纯工具。
4. **有失败案例**：展示 VLM 直接取色的坏结果，比展示成功案例更有说服力。
5. **有成本意识**：默认零 AI、异步追加、断网可用。

一句话：**"我判断了 AI 不该用在哪里"比"我用了 AI"更能证明产品判断力。**

### 6.8 范围纪律

这份讨论会产生大量"还可以做"的念头（多品牌、库存识别、AR 引导、风格化、成品回流校准）。但 `09` 的 v1 范围已经很紧（29×29 单板、MARD+Perler、路径 A+B）。**不要因为讨论里出现了某个 AI 能力就扩 v1。** 新增内容只进"待决 / v2 候选"，不改变当前里程碑。
