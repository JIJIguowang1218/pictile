# 技术方案与关键决策

> 本文档是讨论用的草案，不是定稿。带 `D-` 编号的是待决策项，定下来的写进"已决策"。

## 1. 核心流水线

```
输入（图片 / 文本）
   │
   ├─ 1. 预处理：方向校正、主体检测、智能裁剪、曝光/对比度归一
   │
   ├─ 2. 网格规划：目标板数（29×29 / 多板拼接）→ 输出像素尺寸
   │
   ├─ 3. 像素化：按网格做区域采样（不是点采样），保留结构与边缘
   │
   ├─ 4. 语义简化：合并碎区、强化关键特征、清理孤立豆、可选描边
   │
   ├─ 5. 调色板映射：在候选色板内做感知色差匹配（CIELAB / CIEDE2000）
   │       + 色数上限约束 + 可选抖动（通常不建议，会制造噪点）
   │
   ├─ 6. 图纸生成：网格线、行列号、色号/符号、分板切分、接缝标记
   │
   └─ 7. 交付：预览图、PDF、用量与成本清单
```

每一步都可调，但默认值必须足够好——绝大多数用户不会去调。

## 2. 关键算法点

### 2.1 降采样比"像素化"更重要

简单最近邻缩放会随机丢像素。正确做法是对每个目标格覆盖的源区域做统计采样：

- 用 **面积平均 / 中值**，在中值上用 **LAB 空间** 而非 RGB，避免亮度偏差。
- 对包含强边缘的格子，用 **边缘感知** 的采样（例如取主导色而非平均色），防止轮廓被抹平。
- 缩得太狠时（比如 500px 宽的图压到 29 格），先做多级预降采样再取格，减少混叠。

### 2.2 调色板映射

- 色差用 **CIEDE2000**，比 RGB 欧氏距离更贴近人眼。
- 直接取最近色会产生"色块噪声"：相邻格在几个近似色之间来回跳。需要加 **区域一致性**
  约束（如 MRF / 简单多数投票平滑 / 中值滤波后再映射）。
- 支持两种模式：
  - **受限色板**：给定色板（某品牌全套 / 用户库存）内匹配。
  - **自由减色 + 映射**：先 k-means / median-cut 减到 N 色，再映射到最近的实际豆色。
- 色数上限可作为硬约束：超出时按"颜色使用频次 × 视觉重要性"合并。

### 2.3 语义简化（这是差异化所在）

- **主体分割**：抠出主体，背景可替换为纯色或留空（拼豆里"留白"= 不摆豆）。
- **显著特征保护**：人脸/眼睛/文字区域在降采样时提高权重，避免被平均掉。
- **碎区清理**：删除 1–2 格大小的孤立色块，或并入周围主色（可配置强度）。
- **轮廓增强**：可选在主体边界加一圈深色豆，显著提升辨识度（拼豆作品的常见技法）。
- **多板切分**：按拼板尺寸切图，相邻板的边缘保持连续，图纸上标注接缝与重叠行。

### 2.4 预览真实感

- 每颗豆画成带圆角/高光的圆点，保留拼板间隙。
- 可选"熨烫后"效果（豆子略微膨胀、融合）。
- 预览只做展示，不影响图纸数据。

## 3. AI 的介入点

按价值排序（也是建议的落地顺序）：

1. **语义理解类（高价值、低成本）**：主体检测、显著区域、文字/人脸识别 → 决定"保留什么"。
   这类可以先用现成模型（分割、检测），不必自己训。
2. **底图生成（可选）**：文本 → 像素风/卡通图，作为输入的一种。要注意生成图本身要适合拼豆
   （简单造型、清晰轮廓），提示词里就应约束。
3. **参数推荐**：根据图片内容推荐板数、色数、是否加描边、背景处理方式。
4. **风格化**：把照片转成适合拼豆的扁平插画风（减少高频细节），这是"AI 辅助"最有感知的部分。

## 4. 候选技术形态

| 形态 | 优点 | 代价 |
| --- | --- | --- |
| Web 应用（后端处理） | 跨平台、易分享、可接 AI API | 需服务器、大图上传、隐私 |
| 纯前端 Web（WASM/Canvas） | 零后端、隐私好、可离线 | AI 模型受限、性能与包体 |
| 桌面端（Tauri/Electron） | 性能好、可离线、可本地模型 | 分发与更新成本 |
| CLI / 库 | 开发快、易验证算法 | 非目标用户用不了 |

早期建议先做**算法内核 + 可验证的 CLI/脚本**，再接一层薄 Web UI。

## 5. 待决策清单

### 产品层

- `D-01` **首要用户是谁**：个人玩家 / 礼物党 / 小店摊主 / 亲子教学？（决定默认色数、板数、专业度）
- `D-02` **输入主形态**：以照片为主，还是文本生成图为主，还是两者并重？
- `D-03` **输出去到哪一步**：只给预览图，还是必须给可打印 PDF + 用量清单？
- `D-04` **色板来源**：绑定具体品牌色板（需要维护色表数据），还是用户自建色板？
- `D-05` **是否收费 / 免费额度**：影响是否接付费 AI API、是否本地推理。

### 算法层

- `D-06` **是否做语义分割**：先上简单启发式（边缘+显著性），还是一开始就上模型？
- `D-07` **是否提供抖动**：拼豆一般不推荐，但可作高级选项。
- `D-08` **多板拼接**是否首版就做？
- `D-09` **色板色值来源与准确性**：各品牌官方色号/色值数据从哪来、如何维护、如何校验。

### 工程层

- `D-10` **技术栈**：Python（图像处理生态强）还是 TypeScript 全栈？
- `D-11` **AI 调用方式**：云端 API / 本地模型 / 不接（先纯算法）。
- `D-12` **目标平台**：Web 优先 / 桌面优先 / 移动优先。
