## 0. 一页结论

1. **不要先筛背景去除算法。** 先有评测底座（图片集 + 指标 + 人工评分），否则算法选择只能靠 demo 截图和直觉。
2. **第一版能跑通的是确定性内核**：单图 → 29×29 → 预览 + PDF/CSV；默认零 AI、零上传。
3. **Web MVP 先做薄切片**：上传 → 出图 → 导图。不做账号、社区、电商、多板、多品牌。
4. **AI 层放在确定性内核与诊断闭环之后**：先语义重要性、特征核对、成对比较，不做自由编排。
5. **手机 App 最后做**：Web 先做成移动优先的 PWA；核心保持语言无关，后续用 RN/Flutter + WASM 或服务端 API。
6. **数据资产是长期投入**：MVP 120 张，v1 300–500 张，阈值标定 1000+。**以用户找的网图为主**（卡通/人物/宠物/logo 占比高），类型按**属性覆盖**，不按品类堆数量。**测试图片本地保存、U 盘拷贝，不进 Git**；清单、结果、评论、索引走 Git 远程同步，换机器用文件名 + sha256 重新定位。

## 1. 开发原则

| # | 原则 | 原因 |
| --- | --- | --- |
| 1 | **评测先行** | 没有基准就没有"更好"，只有"看起来不错" |
| 2 | **确定性内核先行** | 它是产品地板；AI 失败时仍能出图 |
| 3 | **薄切片，再加宽** | 先跑通"上传→出图→导出"，再谈诊断、AI、多板 |
| 4 | **核心语言无关** | 纯函数、JSON 进 JSON 出、不读 IO；Python 验证，Rust/WASM 或服务端复用 |
| 5 | **算法够用即止** | 背景去除是商品能力，不是护城河；2–3 个候选，达标就停 |
| 6 | **默认零 AI** | 成本、延迟、隐私、可控性；AI 由指标触发或用户开启 |
| 7 | **数据不提交仓库** | `data/` 已被 `.gitignore` 忽略；只提交清单与匿名标签 |

### 1.1 代码结构

```
src/pictile/        # 正式算法内核（纯函数，JSON in/out）
tests/tools/        # 测试资产管理（入库、定位、校验、索引）
tests/images/       # 图片本地保存，不进 Git
scripts/            # 一次性脚本（暂存、审核入库）
docs/               # 设计文档
```

规则：正式算法只进 `src/pictile/`；测试工具只进 `tests/tools/`；一次性脚本只进 `scripts/`。不把临时脚本塞进内核。

### 1.2 环境与依赖

- Python 3.11+。
- 运行时依赖：`requirements.txt`。当前实际使用 numpy、opencv、Pillow、reportlab；scikit-image / scipy / colour-science 留作后续算法工作。
- 开发/测试依赖：`requirements-dev.txt`（+ requests、jsonschema、pytest）。

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
pip install -r requirements.txt
pip install -r requirements-dev.txt
```

换电脑先装依赖，再跑测试；`requirements*.txt` 是唯一依赖来源。

## 2. 阶段计划（M0–M5）

| 阶段 | 周期 | 交付 | 验收 | 风险 |
| --- | --- | --- | --- | --- |
| **M0 评测底座** | 1–2 周 | 120 张图 + 标签 + 评测脚本 + 基线 CLI | 20 张跑通，指标可输出 | 标注成本被低估 |
| **M1 确定性内核** | 2 周 | 29×29 单图 → 预览 + PDF/CSV；MARD 221 | 20 张人工评分 ≥3.5/5；1:1 打印 | 色表不准、采样糊边 |
| **M2 Web MVP** | 2–3 周 | 移动优先的 Web：上传 → 预览 → 导出 | 首图 ≤1s；10–20 人可用 | 前端拖慢内核迭代 |
| **M3 诊断闭环** | 2–3 周 | P0 检查项 + top 3 诊断 + simulate + 前后对比 | 决策数 P50 ≤1；诊断有效率 ≥80% | 阈值未标定 |
| **M4 AI 试点** | 2–3 周 | 语义层（主体/脸/文字/logo）+ C12 + 成对比较 + 措辞 | 一致率 ≥0.75；灰度 +5pp | AI 建议反而增加决策 |
| **M5 移动化** | 3–4 周 | PWA → RN/Expo 或 Flutter；相机/相册/分享/离线 | 手机上完成一次真实出图 | 核心移植成本 |

**顺序不能颠倒**：M0 → M1 → M2 → M3 → M4 → M5。M4 之前不要写任何 AI 代码。

## 3. 先做什么：不是先筛背景去除算法

### 3.1 第一周该做的事

1. **写 MVP 规格与验收**：29×29、MARD 221、≤12 色、PDF/CSV、首图 ≤1s。
2. **搭图片集**：先 60 张 dev，覆盖 15 类属性；不够再补到 120。
3. **搭评测脚本**：每张图输出结构化的指标 JSON + 人工评分表。
4. **做基线 CLI**：面积平均 + CIEDE2000 + 最近色映射 + 孤立块清理 + PDF。**先不接任何模型。**
5. **再筛算法**：拿 2–3 个背景去除候选、2 个降采样候选，在评测集上跑，选达标且最简单的。

### 3.2 为什么不是先筛算法

- 没有基准，"哪个背景去除更好"只能看 demo 图；demo 图通常是最好的那张。
- 背景去除只是链路中的一环；它再好，采样、色板、清理、排版不行，成品仍然不能用。
- 先做基线还有一个好处：**后面每个算法都能回答"它比基线好在哪、代价是什么"**。
- 背景去除是商品能力，不是差异化；差异化在"语义重要性 × 属性脆弱性"的复合决策。

### 3.3 算法筛选清单（M0/M1）

| 模块 | 候选 | 指标 | 达标线 |
| --- | --- | --- | --- |
| 背景去除 | rembg/u2netp、BiRefNet、SAM/MobileSAM、PP-HumanSeg | 前景 IoU、边界 F1、发丝/透明、CPU 延迟、内存 | 易例 IoU ≥0.90，难例 ≥0.75；延迟 ≤1s |
| 降采样 | 区域平均、方差门控主导色、超像素引导 | 小物体保留率、边缘模糊、孤立块比例 | 在难例集上优于区域平均 |
| 色板子集 | 贪心 k-medoids、随机重启 | ΔE P95、色数、色阶多样性 | ΔE P95 达标，无"8 个近似色" |
| 细线结构 | 形态学 top-hat / 骨架 | 细线保留 vs 噪点 | 人工 + 特征核对 |
| 人脸 | MediaPipe / YuNet / PFLD | 目标尺度下的五官定位 | 眼睛位置误差 ≤1 格 |
| OCR | PaddleOCR / RapidOCR | 字符数、目标格数下可辨性 | 只做可行性判断，不追求识别率 |
| 检查项 | 08 的 P0 七项 | 结构化输出 + simulate | 每条都有证据与动作 |

**选型规则**：在达标线上选**最简单、最便宜、最稳**的，不追 SOTA。背景去除优先 `u2netp`/`MobileSAM`；发丝和透明物体再考虑 BiRefNet。

## 4. 图片资产计划

### 4.1 规模

| 阶段 | 数量 | 用途 |
| --- | --- | --- |
| M0 冒烟 | 20–30 | 跑通、找明显 bug |
| **MVP 基准** | **120** | 60 dev / 40 eval / 20 edge |
| v1 标定 | 300–500 | 阈值标定、诊断有效率 |
| 长期 | 1000+ | 分类型回归、难例库 |

**不要等到 1000 张再开始。** 先 60 张 dev 跑起来，边做边补。

### 4.2 类型（按属性覆盖，不按品类堆数量）

| 类型 | MVP 数量 | 主要覆盖的属性 |
| --- | --- | --- |
| **卡通 / 动漫角色** | **30** | 平色、硬边、粗轮廓、高对称、少色 |
| **人物 / 人像** | **24** | 五官、肤色、发丝、背景 |
| **宠物 / 动物** | **18** | 毛发高频、细线（胡须）、小主体 |
| **Logo / 扁平图形** | **18** | 形状/颜色身份、少色、细线 |
| 产品 / 食物 / 风景 | 12 | 主体清晰、反光、渐变、背景 |
| 文字 / 截图 / 地图 | 6 | OCR、笔画宽度、直线、细线 |
| 硬负例 / 抽象 / 其他 | 12 | 主体过小、低对比、背景抢色、无明确主体 |

合计 120。**这是用户实际会发的内容分布**：网图为主，卡通、人物、宠物、logo 占比高；手机拍摄只占少量。

> 调整说明：上一版按"手机拍 ≥30%"估算不准确。用户实际输入是**网上找的图**，最终产品的拍照入口是次要来源。图片资产按这个分布准备。

### 4.3 入库结构

图片不手工改名，统一用 `tests/tools/add_image.py` 生成：

- **文件名**：`{stage}-{batch}-{code}.{ext}`，例如 `T01-B20261027A-I0001.jpg`
- **清单**：`tests/manifests/{stage-dir}/{batch}.json`
- **结果**：`tests/results/{stage-dir}/{batch}/{image_id}.json`，一张图可以有多次 run，评论写在 run 里
- **批次总结**：`tests/reviews/{stage-dir}/{batch}.md`，只写结论与决策

完整字段、命名规则、LFS 同步方式见 [`tests/README.md`](../tests/README.md)。

最小元数据示例：

```json
{
  "image_id": "T01-B20261027A-I0001",
  "type": "cartoon",
  "source_kind": "web",
  "source_url": "https://...",
  "license": "unknown",
  "difficulty": 3,
  "notes": "用户找的网图，仅内部测试"
}
```

生成后的人工评分与评论：

```json
{
  "run_id": "R20261027A-01",
  "variant": "29x29_12c_area_mard221",
  "verdict": "pass",
  "failures": [],
  "comment": "脸能认出来，背景有点碎",
  "reviewer": "owner"
}
```

### 4.4 标注成本

- 掩码/框：10–20 分钟/张；可用 SAM 辅助预标，再人工修。
- 生成后评分：2–3 分钟/张。
- 120 张 ≈ 20–30 小时；**先做 T00 20 张 + T01 60 张**，就能启动。
- 标注集是资产，不是开销：它同时用于阈值、回归、AI 评测。

### 4.5 来源与合规

- 用户实际输入以**网图**为主：卡通角色、人物、宠物、logo。测试集可以收录这些图，但**仅限私有仓库、内部测试**。
- 每张图必须记录 `source_kind / source_url / license / notes`；未知许可标 `unknown`。
- **不做二次分发、不公开、不用于商业素材**；公开演示/作品集另建 `demo` 集，只用自有、CC0、已购买或明确授权的图片。
- 人像需本人同意或使用公开许可素材；不提交身份证、私聊截图等敏感内容。
- 测试图片放 `tests/images/`（**不进 Git，已 `.gitignore`**），用 U 盘拷贝；清单、结果、评论、索引正常提交与同步。`data/` 仍是本地临时实验目录。

### 4.6 测试批次与文件管理

**阶段码**：`T00` 冒烟、`T01` 基线、`T02` 背景去除、`T03` 降采样、`T04` 色板、`T05` 诊断、`T06` 语义、`T07` AI 核对、`T08` Web 可用性、`T09` 手机。

**命名**：`{stage}-{batch}-{code}.{ext}`，例如 `T01-B20261027A-I0001.jpg`。
`stage` 是测试阶段，`batch` 是 `BYYYYMMDD` + 字母，`code` 是批次内自增的四位编号。唯一键 = `stage + batch + code`，从路径可反推唯一键。

**三类文件分工**：

| 文件 | 位置 | 内容 |
| --- | --- | --- |
| 批次清单 | `tests/manifests/{stage-dir}/{batch}.json` | 图片身份、来源、许可、类型、哈希 |
| 单图结果 | `tests/results/{stage-dir}/{batch}/{image_id}.json` | 每次 run 的指标、通过情况、你的评论 |
| 批次总结 | `tests/reviews/{stage-dir}/{batch}.md` | 结论、分歧、决策，不重复每张图 |

**工具**：

```bash
python tests/tools/add_image.py --stage T01 --file "C:/img.jpg" \
  --type cartoon --source-kind web --source-url "https://..." \
  --license unknown --difficulty 3 --note "用户找的网图"
python tests/tools/locate_images.py --root "E:/pictile-images" --check-hash --write-config
python tests/tools/validate.py
python tests/tools/build_index.py
```

- `add_image.py` 自动分配编号、统一缩到最长边 1600px、计算 sha256、写清单与空结果。
- `scan_staging.py` 扫描用户拖入的中文类型文件夹，生成 `清单.csv`、总览图与审核表。
- `ingest_staged.py` 只导入审核通过的图，保留来源/许可/哈希与临时文件名映射。
- `archive_staged.py` 把暂存内容**移动**到 `tests/archive/{stage}/{batch}/`，桌面清空但不删除其他东西。
- `locate_images.py` 把同步的清单映射到本机/外接盘的图片根目录，并写 `tests/local.json`。
- `validate.py` 检查命名、路径、哈希、结果结构、孤儿文件。
- `build_index.py` 生成 `tests/index.csv` 与 `tests/index.md`，支持跨批次检索。
- 完整的字段与工作流见 [`tests/README.md`](../tests/README.md)。

### 4.7 图片本地保存与索引同步

- **图片**：本地 `tests/images/`，已被 `.gitignore` 忽略；用 U 盘整目录拷贝，**保持内部结构不变**。
- **同步**：`manifests / results / reviews / index.csv / index.md` 走普通 Git。
- **路径契约**：清单里存 `tests/images/{stage-dir}/{batch}/{file}` 和 sha256；换机器时用文件名 + 哈希定位原图。

```bash
git add tests
git commit -m "test(T01): add batch B20261027A"
git push origin main
```

换机器：

```bash
# 1) 把 U 盘里的图片目录拷到任意位置，例如 E:/pictile-images
# 2) 拉代码
git clone git@github.com:JIJIguowang1218/pictile.git
cd pictile
# 3) 定位图片并写本机配置
python tests/tools/locate_images.py --root "E:/pictile-images" --check-hash --write-config
python tests/tools/validate.py
```

- `tests/local.json` 是本机配置，不进 Git；每台机器生成一次。
- 如果只换根目录、不改文件名，清单路径和哈希都能对上；文件名被改会被哈希检查抓出来。
- 图片不进 Git，但仓库仍建议私有：`tests/index.csv`、结果和评论可能包含来源信息与个人备注。

### 4.8 暂存—审核—入库—归档工作流

1. **暂存**：图片只放在桌面唯一的暂存文件夹里。T00 用 `stage_t00.py` 生成；T01 起由用户拖进中文类型文件夹。
2. **扫描**：`python scripts/scan_staging.py --staging "..."` 生成 `清单.csv`、总览图、审核表；保留原名与相对路径。
3. **审核**：在 `清单.csv` 的 `审核状态` 填 `通过` / `拒绝` / `替换`，备注写原因。
4. **入库**：`python scripts/ingest_staged.py --stage T01 --staging "..."`，只导入 `通过` 的行，自动规范命名、缩图、写清单与结果。
5. **归档**：`python scripts/archive_staged.py --stage T01 --batch <批次> --staging "..."`，把暂存内容**移动**到 `tests/archive/{stage}/{batch}/`。桌面暂存文件夹清空，但不删除桌面上的其他内容。
6. **校验**：`python tests/tools/validate.py`，再 `python tests/tools/build_index.py`。

为什么这样做：人工审核挡在测试库之前；临时文件名方便看类型；来源/许可/哈希在暂存时就记录，入库不丢信息；正式命名只在入库时发生；归档保留原图，桌面不留东西。

### 4.9 审核前端（本地）

T01 的逐张评分用本地审核服务，不写生产前端：

```bash
python scripts/review_server.py --stage T01 --batch B20261026B --open
```

- 一张图：左原图、右处理后图、3cm 预览、尺寸/色数/豆数/ΔE、颜色表。
- 右侧常驻验收标准；分数 + 备注两个主输入，失败标签可选。
- 点确认写入 `out/<stage>/<batch>/review/<image_id>.json` 与 `rating.csv`；未确认草稿存浏览器本地。
- 验收文本、评分口径、失败标签在 `out/<stage>/<batch>/review_config.json`，模板在 `scripts/review_configs/<stage>.json`。**换批次只改这个配置文件，不改前端。**
- 评完运行 `python scripts/aggregate_t01.py --batch <批次>`。

## 5. Web MVP 范围

### 5.1 做什么

- 拖拽/粘贴/手机相册上传；EXIF 方向校正。
- 29×29、MARD 221、≤12 色。
- 网格预览 + 真实感预览 + 3cm 缩略图测试。
- PDF（网格/符号/色号/行列号/10mm 标尺）+ 用量 CSV。
- 可选：1 条诊断 + 一键修复 + 前后对比。

### 5.2 不做什么

账号、社区、作品流、电商、多板、多品牌、文本生图、视频、AR、支付。

### 5.3 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 算法内核 | Python + numpy/opencv/scikit-image/colour-science | 色彩与图像生态最成熟 |
| 后端 | FastAPI（单容器） | 接口薄、易部署、方便后续换 Rust |
| 前端 | Next.js + TypeScript + Tailwind | 移动优先、迭代快、易做 PWA |
| 内部验证 | Streamlit / Gradio | 第一周只看效果，不做产品 UI |
| 导出 | reportlab / WeasyPrint + canvas | PDF 与 PNG |
| 部署 | Vercel + 单容器 | 初期无 GPU |

**核心接口约束**：`render(image, constraints, palette) → grid + metrics`，纯函数、无 IO、JSON 可序列化。这样后续可以整体搬到 Rust/WASM，供手机端离线使用。

### 5.4 网页 → 手机的路径

1. **M2 先做移动优先 Web/PWA**：手机浏览器可完成一次真实出图、导出、分享。
2. **M5 再决定壳**：React Native/Expo 或 Flutter；核心走服务端 API。
3. **离线需求出现后**，再把核心迁到 Rust/WASM；不要在 M2 就上 WASM。
4. **不要在 M2 选原生框架**；先用 Web 验证交互和产出质量。

## 6. 验收指标

| 指标 | MVP 目标 | 测法 |
| --- | --- | --- |
| 首图时间 | ≤1s（服务端） | 埋点 |
| 20 张真实图人工评分 | ≥3.5/5 | 盲评 |

## 7. 主要风险

| 风险 | 表现 | 应对 |

**T01 基线（计划 60 张，实际批次 B20261026B 为 103 张）**：原计划 15 卡通、12 人物、9 宠物、9 logo、6 产品/食物/风景、3 文字/截图、6 硬负例/抽象。实际用户扩充为：卡通 15、人物 15、宠物 14、Logo 10、产品 13、风景 15、文字 7、截图 4、硬负例 10；**正例 93、硬负例 10、未分类 0**。按实际数量纳入，不拒绝多出来的样本。

评分分两组：**正例 93 张**算平均分（目标 ≥3.5/5）；**硬负例 10 张**不参与平均分，单独看系统是否提前警告、是否优雅失败。否则硬负例会无意义地拉低整体分数。由于实际类别数量不均，除微平均外还看**大类均衡平均（macro）**，避免风景/产品等大样本类别主导结论。

**T02 背景去除（30 张）**：10 易例（干净背景、清晰主体）、10 中等（杂背景、相似色）、10 难例（发丝/毛发、透明、细结构）。可以并行收集，但**T01 基线跑通后再测**。

- **评分方法**：1–5 分，先缩到约 3cm 看；填评分、失败标签、评论。

- **结果（2026-10-26）**：**FAIL**。正例平均 **2.40/5**、中位数 **2**、≥3 比例 **41%**；Logo **3.80**、截图 **3.50**（n=4），其余类型均 <2.5；宠物 **1.93**；硬负例 **1.60**。详见 [`14-T01结果与尺寸适配分析`](14-T01结果与尺寸适配分析.md)。
