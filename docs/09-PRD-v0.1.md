## 1. 产品定义

**一句话**：让没有美术基础的人，在 5 分钟内拿到一张"买得到豆子、拼得完、还认得出"的图纸。

**不做什么**：不做像素化玩具，不做通用修图，不做社区与电商。

**核心命题**：拼豆图纸的价值不在"生成"，而在**判断**——判断哪些细节必须保留、哪些可以牺牲、牺牲的代价是什么。竞品把这件事交给用户的直觉和一堆全局滑杆；我们的解法是**系统先判断，用户只做取舍**。

### v0.1 关键取舍（PD）

| ID | 决策 | 理由 |
| --- | --- | --- |
| PD-01 | 首要用户：个人玩家 / 送礼者 | 29×29 小挂件是最高频、最低门槛场景；小店与亲子放后续 |
| PD-02 | 主输入：照片；插画次之；**文本生图不做** | 文本生图成本高、可控性差，且不是当前痛点 |
| PD-03 | 主交付：可打印 PDF + 用量 CSV + 预览 PNG | 竞品已验证这是刚需；也是"专业感"的来源 |
| PD-04 | v1 色板：MARD 221 + Perler 103；Artkal 放 v1.1 | MARD 是国内主流，Perler 覆盖海外用户 |
| PD-05 | v1 板型：29×29 单板；多板放 v1.1 | 先验证"判断力"，不先验证工程 |
| PD-06 | AI **默认不介入**，诊断按需触发 | 控制成本、延迟与不可控风险 |
| PD-07 | 确定性内核跑在浏览器；AI 在服务端 | 隐私、首屏速度、拖滑杆实时性 |
| PD-08 | v1 不做账号、社区、电商 | 与核心价值无关 |

## 2. 用户与场景

| 画像 | 场景 | 核心诉求 | 失败模式 |
| --- | --- | --- | --- |
| **小白玩家**（首要） | 把宠物/爱豆/角色照片做成 29×29 挂件 | 别让我调参数，直接给我能拼的 | 拼到一半发现眼睛没了 |
| **送礼者** | 做 2–4 板的人像/风景送人 | 要好看、要拿得出手、要知道花多少钱 | 成品不像本人 |
| **小店摊主**（后续） | 批量出图接单 | 快、稳定、成本可控 | 每张图质量不稳定 |

**共同痛点**：不知道"哪里出了问题"，也不知道"改了会怎样"。

## 3. 竞品格局与我们的位置

国内同类产品已进入红海，且**功能高度同质**：色板齐全、限定色数、分板分页、用量清单、抖动开关。其中交付物最完整的是 beadsheet，参数最丰富的是开源项目 Hon-Wong/pindou。

但九家竞品的共同盲区一致：**全部是全局参数 + 一键生成，没有区域级控制、没有质量诊断、没有解释、没有成本金额、没有可行性预判。**

我们的位置不是"功能更多"，而是 **"每一步都知道为什么"**。

## 4. 核心体验：三条路径

### 路径 A：默认路径（0 决策，覆盖 70–80%）

```
上传 → 自动裁剪/主体识别 → 默认参数出图 → 轻微问题自动修正 → 完成
```

用户什么都不用做。系统在后台跑检查项，只有 `problem` 级问题才会打断。
**验收标准：这条路径必须能独立走完，不依赖任何 AI。**

### 路径 B：诊断修复（1 决策，覆盖剩余大部分）

```
出图 → 体检 → 最多 3 条诊断（带代价）→ 一键修复 → 前后对比 → 接受/换一个
```

每条诊断的固定格式：

> **问题**：左眼和背景混在一起，五官不可辨
> **原因**：色板里最接近的深灰比原图亮 7，眼睛区域被量化成一整块
> **建议**：加一圈深色描边（1 颗豆宽）
> **代价**：+1 色、+12 颗豆、+2 分钟
> **预计效果**：轮廓保真 0.61 → 0.78

### 路径 C：对话收敛（多次，覆盖少数高要求用户）

```
"眼睛再大一点，背景去掉那把椅子" → 系统定位区域 → 局部重算 → 前后对比
```

自然语言只用于**定位与意图**，不用于生成像素。

### 交互铁律

1. 用户每张图**最多 1 次决策**，每次最多 3 个选项。
2. 任何自动变更必须可撤销，且能显示 diff（几格/几色/几颗豆/几块钱）。
3. 任何建议必须带代价；没有代价的建议不呈现。
4. 任何 AI 结论必须能展开看到"哪个检查项、哪个数值"。

## 5. 功能需求

### 5.1 MVP（v0.1）

| 模块 | 需求 | 优先级 |
| --- | --- | --- |
| 导入 | 拖拽/粘贴/选择图片；EXIF 方向校正；常见格式 | P0 |
| 预处理 | 主体检测、方形裁剪、背景处理（保留/纯色/留空） | P0 |
| 网格 | 29×29，可改 14×14 / 58×58；保持比例不拉伸 | P0 |
| 采样 | 面积平均（默认）+ 边缘保留；多级预降采样防混叠 | P0 |
| 量化 | 给定色板子集选择（k-medoids 贪心 + 交换精化）；色数上限 | P0 |
| 清理 | 孤立块移除、碎区合并（强度可设默认） | P0 |
| 预览 | 网格预览 + 真实感预览（豆粒/间隙） | P1 |
| 体检 | 执行 `08` 中 P0 检查项，输出 top 3 诊断 | P0 |
| 修复 | 支持 A01/A03/A04/A05/A10 五个动作，带 simulate | P0 |
| 导出 | PDF（网格+符号+色号+行列号+10mm 标尺）、用量 CSV、PNG | P0 |
| 成本 | 豆数（含 10% 损耗）、袋数、金额、预估工时 | P1 |

### 5.2 v1.1

| 模块 | 需求 |
| --- | --- |
| 多板 | 2×2 与 1×2/2×1；接缝标线；错缝建议（C17） |

### 5.3 v2（方向，不承诺）

- 对话式局部修改（路径 C）
- 跨品牌色号等价
- 豆盒拍照识别 + 缺色补货建议
- 照片 → 拼豆友好底图（风格化）

### 5.4 明确不做

- 文本生成底图
- 社区、作品流、电商
- 3D/立体拼豆
- 自动拼装（AR 引导）——待验证

## 6. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 首屏 | 上传到出图 ≤ 1s（浏览器本地，29×29） |
| 交互 | 参数变更重算 ≤ 100ms；拖拽预览 ≥ 30fps |
| AI 延迟 | 诊断 ≤ 8s；超时则不显示 AI 结论，退回确定性体检 |
| 隐私 | 默认不上传；启用 AI 时才上传，24h 删除，不用于训练 |
| 成本 | 单图 AI 成本目标 ≤ ¥0.05；默认路径为 0 |
| 可用性 | 断网可用（除 AI 与导出分享） |
| 打印 | 1:1 校验：页面内印 10mm 标尺 |
| 可访问性 | 色盲安全：符号 + 色号双编码 |

## 7. 数据与色板

- **色板版本化**：`palette_id + version`，每条色值带 `source`（官方 / 社区 / 实测）与 `measured_at`。
- v1 用公开 HEX 近似值起步，数据模型预留 `lab_measured` 覆盖位；算法只读 LAB，HEX 仅用于展示。
- 色数口径差异（MARD 185/221/264/291）通过"色板版本 + 套装范围"表达，不假设唯一真值。
- 图纸必须记录所用色板版本，否则不可复算。

## 9. 交付物规格

**PDF**
- A4，1:1 打印；每页角标 10mm 标尺条。
- 网格线：每格细线，每 5 格中粗，每 10 格粗。
- 格内：符号 + 色号（符号优先，保证黑白打印可读）。
- 页脚：板号、行列范围、接缝标记、图案总尺寸。
- 多板：按板分页，接缝处标注相邻板号。

**CSV**
- 列：色号、名称、HEX、格数、豆数（含 10% 损耗）、袋数。
- 汇总：总豆数、总色数、板数、预估工时、金额。

**PNG**
- 图纸（含色号）与真实感预览各一份。

## 10. 指标与验收

| 指标 | 目标 | 测法 |
| --- | --- | --- |
| **决策数 / 图** | P50 ≤ 1，P90 ≤ 2 | 埋点 |
| **首次接受率** | ≥ 60% | 用户未做任何修改即导出 |
| **收敛轮次** | ≤ 2 | 从首次出图到导出之间的修改次数 |
| **诊断采纳率** | ≥ 40% | 呈现的诊断被点击修复的比例 |
| **诊断有效率** | ≥ 80% 的采纳确实使 `severity` 下降 | simulate 预测 vs 实测 |
| **AI 有帮助率** | 相对无 AI 版本，接受率提升 ≥ 5pp | 灰度 A/B |
| **出图时长** | P90 ≤ 5 分钟 | 埋点 |
| **打印保真** | 1:1 误差 0 | 标尺实测 |

## 11. 风险与边界

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 公开色值不准（HEX 仅为近似） | 成品色偏 | 版本化 + 实测覆盖；诊断中明示"近似" |
| 市场已红海 | 获客难 | 不打功能战，打"解释与判断" |
| AI 成本/延迟 | 体验崩 | 默认零 AI；超时降级 |
| VLM 判断不稳 | 建议错误 | 成对 + 换位 + 多票；白名单动作 + simulate 驳回 |
| 版权与肖像 | 法律风险 | 用户协议；不做成品代售 |
| 色板数据授权 | 下架风险 | 优先用公开近似值；实测数据自建 |

## 13. 开放问题

1. 符号体系：自建还是沿用十字绣符号表？符号数量上限与可读性。
2. 成本数据的来源：豆子单价按品牌/渠道差异很大，取什么口径。
3. 阈值标定所需的人工标注成本与人力。
4. 是否允许"混品牌"（一张图用两种品牌的豆），这会影响等价表的设计。
5. AI 灰度策略：默认关 vs 按图自动开启。
